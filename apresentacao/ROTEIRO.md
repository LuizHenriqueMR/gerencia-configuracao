# Roteiro para três pessoas

## Luis Fernando — Introdução e GitHub (cerca de 2 minutos)
"Boa noite. Nosso trabalho reúne quatro entregas de Gerência de Configuração em um único repositório no GitHub. Vou mostrar rapidamente a estrutura. Na página inicial temos o README com links para cada entrega. Aqui está o código Java da Entrega 2, aqui o workflow do GitHub Actions e aqui a execução aprovada. Na aba Issues temos cinco tarefas e no Project elas estão organizadas em duas releases. Agora meus colegas vão explicar o conteúdo no PDF."

**Na tela:** abrir o [repositório](https://github.com/LuizHenriqueMR/gerencia-configuracao), a pasta entrega-2, a [execução bem-sucedida](https://github.com/LuizHenriqueMR/gerencia-configuracao/actions/runs/38477334046) e a aba Issues.

## Luiz Henrique — Somente apresentação (cerca de 3 minutos)
"Na Entrega 1, pesquisamos doze conceitos do Git. Branch é uma linha separada de desenvolvimento; merge integra alterações; baseline é uma versão aprovada, que podemos identificar com uma tag. Também mostramos repository, mainline, workspace e os outros termos. Na Entrega 2, criamos um sistema de construção Java com Maven. O GitHub Actions automatiza compilação, testes, geração do executável, relatórios e documentação. A execução foi aprovada no GitHub."

## Regyane Tavares — Somente apresentação (cerca de 3 minutos)
"Na Entrega 3, criamos cinco issues e distribuímos em duas releases: três tarefas na primeira e duas na segunda. Na Entrega 4, definimos três papéis: desenvolvedor, gerente de configuração e responsável pela qualidade. O diagrama de atividades mostra o fluxo das tarefas, desde o controle de versão até a validação final. Se surgir um problema, o processo retorna para correção e nova verificação."

## Fechamento
"Assim, cada ferramenta e cada papel têm uma função no desenvolvimento e na organização do projeto."
